# D4 Project integration

> D4 is an open-source sensor network for distributed network monitoring by CIRCL. Tenzir acts as a D4 analyzer that consumes pcap files and passive DNS records from the analyzer queues of a D4 server.

[D4](https://www.d4-project.org/) is an open-source sensor network for distributed network monitoring, developed by [CIRCL](https://www.circl.lu/). Sensors stream their data to a D4 server, which hands it to analyzers through queues in [Redis](redis.md).

Tenzir acts as a D4 analyzer with [`from_redis`](https://tenzir.com/docs/reference/operators/from_redis.md), which pops the items of an analyzer queue in the order that the server pushed them.

## Set up an analyzer queue

A D4 server keeps one queue per analyzer in database 2 of its metadata Redis server, which listens on port 6380 by default. The key of a queue has the form `analyzer:<type>:<uuid>`, where `<type>` is the D4 data type and `<uuid>` identifies the analyzer.

Create the queue in the web interface of the D4 server under **Server Management**. Then point [`from_redis`](https://tenzir.com/docs/reference/operators/from_redis.md) at the queue:

```tql
from_redis "analyzer:8:<uuid>", url="redis://d4.example.org:6380", db=2
```

The D4 server pushes every item to the left end of the queue, which is what [`from_redis`](https://tenzir.com/docs/reference/operators/from_redis.md) expects by default. The server trims a queue to its maximum size and drops the oldest items when an analyzer falls behind.

## Examples

### Analyze pcap files

For data type 1, a D4 worker writes the traffic of a sensor to gzip-compressed pcap files and pushes their file names to the queue. Tenzir must run on a machine that can read these files. Decode their packets with [`each`](https://tenzir.com/docs/reference/operators/each.md):

```tql
from_redis "analyzer:1:<uuid>", url="redis://d4.example.org:6380", db=2
each {
  from_file string($this.message) {
    decompress_gzip
    read_pcap
  }
}
this = decapsulate(this)
```

### Parse passive DNS records

For data type 8, the queue holds passive DNS records in the form `timestamp||ip-src||ip-dst||class||q||type||v||ttl||count`:

```tql
from_redis "analyzer:8:<uuid>", url="redis://d4.example.org:6380", db=2
this = string(message).parse_xsv(field_separator="||", list_separator=";",
  null_value="", header=["timestamp", "src_ip", "dst_ip", "class", "query",
  "type", "answer", "ttl", "count"])
timestamp = from_epoch(timestamp * 1s)
```

### Hand results to another analyzer

Push results to the queue of another analyzer with [`to_redis`](https://tenzir.com/docs/reference/operators/to_redis.md), which pushes to the left end of a list by default, like a D4 server:

```tql
to_redis "analyzer:8:<uuid>", url="redis://d4.example.org:6380", db=2,
  message=line
```
